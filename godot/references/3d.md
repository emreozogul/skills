# Godot 4 — 3D mode (low-poly action games)

Same skill, 3D. The *concepts* from the 2D refs port — `enum`+`match` state machines, the Health/Hurtbox/Hitbox composition, the game-feel checklist, the `Events` bus, the run-to-verify discipline. This file is the 3D-specific swaps. Pairs with `asset-pipeline` (Kenney/Quaternius/Synty low-poly packs) for the art.

**Low-poly is the fast lane for a solo dev** because cohesive rigged+animated CC0/$ packs exist — you *assemble* a world instead of modeling it. Build the game in one pack's style; see `asset-pipeline` → the `lowpoly` tag.

> **Verified slice** (Godot 4.6.2, `errors:[]`): a `Player3D` + `FollowCamera3D` + `Chaser3D` slice runs clean — player lands on the floor and moves camera-relative; the chaser finds the player via the `"player"` group and closes 11.46→1.37 units. **Two-way combat verified**: player→enemy and enemy→player `Hitbox3D`→`Hurtbox3D`→`Health` both deal damage (with knockback, white flash, hit-pause, and `GameFeel` 3D shake, trauma 0.31); a **dodge grants real i-frames** (the player's Hurtbox `monitorable` is disabled → 0 damage); and a **HUD** healthbar stays in sync via the Health signal. The snippets below are that verified code.

## The look (set once)

- **WorldEnvironment** + a **DirectionalLight3D** (the sun). Add an HDRI from the vault as `Environment.sky` for free ambient light + reflections (`ph-hdri-*`).
- Low-poly reads best with **slightly soft shadows + flat-ish lighting**. Packs ship their own materials — don't fight them.
- Optional "pixel-3D" stylization: render the game to a low-res `SubViewport` and upscale (PS1 vibe). Skip until the loop is fun.
- Texture filter: low-poly atlases usually want **Nearest** if the texture is pixel-art, else leave default.

## Player — CharacterBody3D (camera-relative)

```gdscript
class_name Player3D
extends CharacterBody3D

@export var speed := 6.0
@export var accel := 40.0
@export var turn_speed := 12.0
@export var gravity := 20.0

@onready var model: Node3D = $Model              # the imported .glb instance
# Optional: placeholder boxes have no AnimationPlayer, real .glb packs do.
@onready var _anim: AnimationPlayer = get_node_or_null("Model/AnimationPlayer")

func _ready() -> void:
	add_to_group("player")                        # so enemies find us via the group

func _physics_process(delta: float) -> void:
	var in2 := Input.get_vector("move_left", "move_right", "move_up", "move_down")
	# Camera-relative: "up" = away from the camera, whatever its yaw. Fetch the
	# active camera each frame (it can change) rather than caching it @onready.
	var cam := get_viewport().get_camera_3d()
	var yaw := cam.global_rotation.y if cam else 0.0
	var dir := Vector3(in2.x, 0.0, in2.y).rotated(Vector3.UP, yaw)

	var target := dir * speed
	velocity.x = move_toward(velocity.x, target.x, accel * delta)
	velocity.z = move_toward(velocity.z, target.z, accel * delta)
	velocity.y -= gravity * delta            # manual gravity in 3D
	move_and_slide()                          # uses velocity (Vector3), no args

	if dir.length() > 0.1:
		model.rotation.y = lerp_angle(model.rotation.y, atan2(dir.x, dir.z), turn_speed * delta)
		if _anim and _anim.has_animation("Walk"): _anim.play("Walk")   # guard: anim names vary by pack
	elif _anim and _anim.has_animation("Idle"):
		_anim.play("Idle")
```

## Camera — fixed-angle follow (ARPG/Moonlighter-style)

For a top-down-ish action RPG, a fixed-angle camera that *follows position but never rotates* reads cleanly. (For over-shoulder, use a `SpringArm3D`; for the no-code path, **Phantom Camera** does 3D too — see `ecosystem.md`.)

```gdscript
extends Camera3D
## Drop in the level; set `target` to the player. High + back = ~50° down.
@export var target: Node3D
@export var offset := Vector3(0, 13, 10)
@export var follow := 8.0

func _physics_process(delta: float) -> void:
	if not target: return
	global_position = global_position.lerp(target.global_position + offset, follow * delta)
	look_at(target.global_position, Vector3.UP)   # guard: target must differ from cam pos
```

## Importing pack models (.glb)

1. Drop the `.glb` (Kenney/Quaternius/Synty/AI export) into the project → Godot imports it as a scene: `MeshInstance3D` + `Skeleton3D` + **`AnimationPlayer`** (the rig's clips).
2. Instance it as the player's `Model` child. Play clips by name: `anim.play("Run")`. (Packs name them `Idle`/`Walk`/`Run`/`Attack`/`Die`.)
3. **Collision is separate from the visual** — add a `CollisionShape3D` (a `CapsuleShape3D` for a character) directly on the `CharacterBody3D`, sized to the model. For static level geometry, use the importer's *Create Trimesh Collision* (advanced import) or a `StaticBody3D`.
4. **Scale check:** glTF is Y-up, meters. Synty/Kenney are ~1 unit = 1 m. If a model is 100× off, fix scale on import, then `Ctrl+A`-equivalent isn't needed — set import scale.

## Combat — Area3D hit detection (same composition)

Reuse the `Health` node from `combat-components.md` verbatim (it's dimension-agnostic). The boxes become 3D:

```gdscript
class_name Hurtbox3D
extends Area3D
@export var health: Health
func _ready() -> void:
	if health == null:
		health = get_parent().get_node_or_null("Health")
func receive_hit(_damage: int, _from: Vector3) -> void:
	if health: health.take_damage(_damage)   # the entity's on_hurt handles the 3D direction
```
```gdscript
class_name Hitbox3D
extends Area3D
signal hit(target: Node)
@export var damage := 6
@export var knockback := 6.0      # metres/sec impulse
func _ready() -> void:
	monitoring = false
	area_entered.connect(_on_area_entered)
func activate() -> void: monitoring = true
func deactivate() -> void: monitoring = false
func _on_area_entered(a: Area3D) -> void:
	if a is Hurtbox3D:
		(a as Hurtbox3D).receive_hit(damage, global_position)
		var t := a.get_parent()
		if t and t.has_method("on_hurt"): t.on_hurt(global_position, knockback)
		GameFeel.hit_pause(6)
		GameFeel.shake(0.35)
		hit.emit(t)
```
Mount the Hitbox3D on a `HitboxPivot: Node3D` and keep `pivot.rotation.y = model.rotation.y` so it aims where you face; `activate()` on the swing's active frames. The struck entity's `on_hurt(from: Vector3, force)` applies knockback (`velocity += (global_position - from).normalized() * force`, zero the Y) + flash. Collision layers: same scheme as 2D (`combat-components.md`); 3D bodies use the **3D** layer/mask.

## Game feel in 3D — what ports, what changes

| Effect | 3D change |
|---|---|
| **Hit-pause** | **Identical** — `Engine.time_scale` is global. The `GameFeel.hit_pause()` from `game-feel.md` works as-is. |
| **Screen shake** | Now on **Camera3D**. `GameFeel` keeps trauma + decay (shared with 2D); your `FollowCamera3D` adds `GameFeel.shake_offset_3d()` to its `global_position` **after** the follow-lerp (a Vector3, ≈0.25 m max, trauma² falloff). Verified firing (trauma 0.31). |
| **Knockback** | A **Vector3** on the XZ plane: `velocity += (global_position - from).normalized() * force` (zero the Y). Verified. |
| **Hurt flash** | Flash the model's material: a unique `StandardMaterial3D` override, tween `emission_energy_multiplier` 3→0 (modulate doesn't exist on 3D meshes). Make the material per-instance or every enemy flashes. Verified. |
| **Squash/stretch** | Scale the **Model** `Node3D`: `model.scale = Vector3(1.15, 0.8, 1.15)` then tween back. |
| **Damage popup** | A `Label3D` (billboarded) at the hit point, tween up + fade. |

So `GameFeel` is dimension-aware: trauma decays in `_process` regardless of camera; the 2D path writes `Camera2D.offset`, the 3D path exposes `shake_offset_3d() -> Vector3` for a follow camera to consume. **Hit-pause, knockback, flash, and shake are all verified in 3D** (enemy 30→0 HP, trauma 0.31). Player attack (`Hitbox3D.activate()` on active frames) + dodge (i-frame burst) are in `Player3D`.

## Getting hit — i-frames + HUD

Give the **player** the same parts as an enemy: a `Health` node + a `Hurtbox3D` (layer = player_hurtbox, mask 0). The enemy gets its own `Hitbox3D` (layer = enemy_hitbox, mask = player_hurtbox) that activates when in range. Now it's a fight both ways — verified.

**Real dodge i-frames:** don't just early-return in `on_hurt` (the damage already flowed through `Health`). Disable the player's Hurtbox for the window so the enemy hitbox can't even detect it:
```gdscript
func dodge() -> void:
	_dodging = true
	hurtbox.set_deferred("monitorable", false)   # ← true i-frames
	# ...burst...
	await get_tree().create_timer(dodge_time).timeout
	_dodging = false
	hurtbox.set_deferred("monitorable", true)
```
(Verified: 0 damage taken while dodging through an active enemy swing.)

**HUD** — a `CanvasLayer` (works over 2D or 3D) that binds a `ProgressBar` to a `Health` and updates on its `health_changed` signal — no reference to the player, just the signal:
```gdscript
func bind(h: Node) -> void:
	bar.max_value = h.max_health; bar.value = h.current
	h.health_changed.connect(func(cur, mx): bar.max_value = mx; bar.value = cur)
```
Verified staying in sync as the player took damage.

## Enemy AI — chase

**Direct chase (verified, no navmesh)** — the default for open arenas/islands. Finds the player via the `"player"` group; closes distance on the XZ plane and hands off near `stop_distance` (to an attack state).

```gdscript
extends CharacterBody3D
@export var speed := 3.5
@export var stop_distance := 1.4
var target: Node3D
func _ready() -> void:
	target = get_tree().get_first_node_in_group("player")
func _physics_process(delta: float) -> void:
	if target:
		var to := target.global_position - global_position
		to.y = 0.0
		if to.length() > stop_distance:
			var dir := to.normalized()
			velocity.x = dir.x * speed
			velocity.z = dir.z * speed
		else:
			velocity.x = move_toward(velocity.x, 0.0, speed)
			velocity.z = move_toward(velocity.z, 0.0, speed)
	velocity.y -= 20.0 * delta
	move_and_slide()
```

**NavigationAgent3D (for maze-like levels)** — same loop, but route through a baked navmesh so the enemy goes *around* walls:
```gdscript
@onready var agent: NavigationAgent3D = $NavigationAgent3D
func _physics_process(delta: float) -> void:
	if not target: return
	agent.target_position = target.global_position
	var dir := (agent.get_next_path_position() - global_position).normalized()
	velocity.x = dir.x * speed; velocity.z = dir.z * speed
	velocity.y -= 20.0 * delta
	move_and_slide()
```
Requires a **`NavigationRegion3D`** with a baked `NavigationMesh` over the level (bake it in the editor; agents need `await get_tree().physics_frame` before the first query). The player must be in the `"player"` group (`add_to_group("player")` in its `_ready`). Start with direct chase; add a navmesh only when geometry demands it.

## 3D gotchas

- `move_and_slide()` — no args; set `velocity: Vector3`; gravity is **manual** (`velocity.y -= g*delta`).
- `look_at(target, UP)` **errors if target == position** — guard, or use it only on a camera that's offset.
- Smooth turning: `lerp_angle(model.rotation.y, target_yaw, k*delta)`, not raw `=`.
- Rotate the **model child**, not the `CharacterBody3D` (rotating the body spins its collision + camera basis).
- Navigation needs a frame to sync: `await get_tree().physics_frame` before the first `get_next_path_position()`.
- `get_viewport().get_camera_3d()` returns the active camera — handy for camera-relative input.
- Group lookup: `get_tree().get_first_node_in_group("player")` beats hard `$"../../Player"` paths.
